# Evaluation: does speechready make the audio better?

This harness answers the plan's go/no-go question. Every corpus line is synthesized twice per provider, as written and after `speechready.prepare`, both audios are transcribed, and the transcripts are scored against the intended words. The output is a table of misread rates per problem class and a before/after page with audio players for listening.

## Corpus

- Every input from the shared fixtures in `spec/fixtures` whose expected output is a spoken form (the verbalize, clean, pipeline and lexicon files), tagged by class.
- `corpus/control.*.yaml`: plain prose that the library must leave alone. Any regression here is a bug.
- `corpus/llm.*.yaml`: realistic assistant answers with markdown, prices, order numbers and phone numbers.
- `corpus/heldout.*.yaml`: the independent check. 30 user turns per language that a voice agent would hear, answered by `gpt-4.1-mini` as a chat assistant with no instruction about speech, after the rules were written; the same model wrote the narration a reader would speak for each answer in a separate call, and that is the reference. Nothing hand-edited. Generated by `python -m speechready_eval.heldout`; reported in its own section of `summary.md` and kept out of the headline numbers, since the rest of the corpus is mostly the fixture inputs the rules were developed against.

## Run

```
python -m pip install -e python -e "eval[whisper,local]"   # faster-whisper (a GPU makes large-v3 fast; a laptop CPU runs it at about 1.5x the audio length) plus Kokoro and Piper
set -a; source .env; set +a                                 # keys live in .env (gitignored), never in the repo

python -m speechready_eval.run --dry-run                       # what would be synthesized
python -m speechready_eval.run --locales en --providers openai --stt openai --limit 10   # a cheap first pass
python -m speechready_eval.run                                 # everything: en + tr, every provider with a key or an installed package, local whisper
python -m speechready_eval.run --providers kokoro,piper        # the local models only: no keys, no spend
python -m speechready_eval.report                              # eval/out/summary.md and eval/out/index.html
```

Results accumulate in `eval/out/results.jsonl`; a rerun skips finished variants, so a crash or a key running out loses nothing. Providers run in parallel with one worker each, so no provider sees concurrent requests. Pass `--voice provider:model:voice:locale` to change voices (defaults are in `synth.py`); providers whose keys or packages are missing are skipped with a notice.

## Local models

These run on the machine, so the only cost is time. They need `ffmpeg` on the path (the audio is stored as MP3 like everything else) and the model package; a provider whose package is not installed is skipped.

| Provider | Voices in the default run | Install |
| --- | --- | --- |
| Kokoro | kokoro-82m `af_heart`, en | `eval[local]` (the `kokoro` package; `espeak-ng` for out-of-vocabulary words). Weights download from Hugging Face on first use. |
| Piper | `en_US-lessac-medium`, `tr_TR-dfki-medium` | `eval[local]` (`piper-tts`), then `python -m piper.download_voices en_US-lessac-medium tr_TR-dfki-medium --data-dir eval/models/piper` (or fetch the `.onnx` and `.onnx.json` from `rhasspy/piper-voices` on Hugging Face into that folder). |
| Chatterbox | chatterbox-multilingual, built-in voice, en + tr | `pip install chatterbox-tts`; a GPU in practice. `--voice chatterbox:chatterbox-multilingual:/path/to/clip.wav:en-US` clones a reference clip. |
| XTTS v2 | `Ana Florence`, en + tr | `pip install coqui-tts`; a GPU in practice. Non-commercial licence. |
| Orpheus | orpheus-3b-0.1-ft `tara`, en | `pip install orpheus-speech` (vLLM, a GPU). |

Model files land in `eval/models/` (gitignored) or the Hugging Face cache. On macOS, PyTorch models (Kokoro, Chatterbox) and faster-whisper cannot share a process: each brings its own OpenMP runtime and the second one aborts or hangs. Run those providers with `--synth-only` first, then the normal run transcribes the clips it finds (Piper's onnxruntime and Whisper coexist fine):

```
python -m speechready_eval.run --providers kokoro --synth-only
python -m speechready_eval.run --providers kokoro,piper
```

On an Intel Mac, PyTorch stops at 2.2, which needs `transformers<4.50`, `tokenizers<0.22`, `numpy<2` and `av<14` beside the current `kokoro` and `faster-whisper`; Apple silicon and Linux need none of that.

The GPU models run from one script on a CUDA machine, `bash eval/gpu/run.sh [chatterbox,xtts,orpheus]`, which makes one venv per model (their torch and vLLM pins disagree), writes the clips with `--synth-only`, then transcribes everything with faster-whisper on the GPU. It was run on a RunPod Secure RTX 4090 ($0.89 an hour at the time) with the image `runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404`: about 25 minutes of installs and downloads, 70 minutes for Chatterbox (424 clips), 15 for XTTS v2 (424), 35 for Orpheus (238) and 5 for Whisper on the GPU; with the retries described below the pod ran three and a quarter hours, about $3 at the published rate including the 80 GB container disk. Pins that mattered: `setuptools<81` (Chatterbox's watermarker imports `pkg_resources`), `transformers<5` beside vLLM 0.7, `av<14` beside faster-whisper 1.2; the `spacy-pkuseg` Chinese segmenter that Chatterbox installs fetches a model from GitHub releases on first use and is removed since this corpus has no Chinese. Orpheus weights come from the `unsloth/orpheus-3b-0.1-ft` mirror because the canopylabs repository is gated, and the harness raises the package's 1,200-token cap (14 seconds of speech) to 7,000 so long answers are not cut off. Copy `eval/out/results.jsonl` and `eval/out/audio` back and run `report` and `showcase` as usual; rows synthesized elsewhere merge by key.

Raw text is sent as plain text everywhere. Processed text is sent the way its profile says: an SSML body wrapped in `<speak>` for Azure, Polly and Google's classic voices, plain text for the rest.

Scoring: word error rate against the intended words. The transcript is normalized the way STT engines write speech: punctuation and markup stripped, symbols turned into words (`+`, `%`, `$`, `TL`, `°C`, `™`, `&`), glued letters and digits split (`AB12X9`), a Turkish `3.` before a lowercase word read as the ordinal, a Turkish acronym also tried with the English letter names speechready writes out (`NPM` against `en pi em`), and every digit run tried as a cardinal, digit by digit, a year or an ordinal, with the best combination counting; as one more candidate the whole transcript goes through speechready's own verbalizer. These allowances only lower the score and apply to both sides equally. A line is a misread when WER is above 0.2. Expected texts from the clean-stage fixtures are passed through the pipeline first, since the eval runs the whole pipeline.

```
python -m speechready_eval.report            # summary.md: per provider, per class, per rule family; index.html: every pair with audio
python -m speechready_eval.showcase --site ../docs   # out/showcase/ plus a standalone copy in docs/, which GitHub Pages serves
python -m speechready_eval.run --redo REGEX  # re-synthesize the processed variant of lines a library change affected
```

## What success looks like

From the plan: the misread rate on the targeted classes at least halves on every provider, with no measurable regression on the control class. Any rule family that does not improve is dropped from the defaults before the first release.

Costs: synthesis is billed per character by each provider at their published rates; the corpus is a few thousand short lines per provider. STT is free with local whisper, or billed per minute with `--stt openai`.
